## 2. Requirements

### REQ-01: Monthly Budget — `/budget`

**Current state:** Бюджета нет.
**Target state:** Пользователь может установить общий месячный бюджет и видеть текущий статус.

**Описание:**
- `/budget` без аргументов — показывает текущий статус: потрачено X из Y (процент, прогресс-бар)
- `/budget 50000` — установить бюджет на текущий месяц
- `/budget 0` — удалить бюджет
- Прогресс-бар: `███████░░░ 70%`
- Если бюджет не установлен — `/budget` пишет «Бюджет не установлен. Используй /budget СУММА»

**Хранение:**
- Google Sheets, лист **Budgets**
- Колонки: Month, Category, Limit, Type (общий / по категории)
- Для общего бюджета: Category = "Общий"
- Чтение с кэшированием в memory (поля user_data / глобальный dict)

**Валидация:**
- Сумма > 0
- Только целые числа (округление до гривны)
- Если бюджет уже установлен на этот месяц — перезаписывается с подтверждением

**Acceptance:**
1. `/budget` без лимита → «Бюджет не установлен»
2. `/budget 50000` → «Бюджет 50000₴ на июнь установлен» + кэширован
3. После трат: `/budget` → «Потрачено 12300₴ из 50000₴ (25%)» + прогресс-бар

### REQ-02: Category Limits — `/set_limit`, `/limits`

**Current state:** Лимитов по категориям нет.
**Target state:** Пользователь устанавливает лимиты на отдельные категории и видит сводку.

**Описание:**
- `/set_limit категория сумма` — установить лимит
- `/set_limit кофе 3000` — лимит на кофе 3000₴/месяц
- `/set_limit кофе 0` — удалить лимит на категорию
- `/limits` — таблица всех лимитов с текущими тратами:

```
🛑 Лимиты на июнь
─────────────────
☕ Кофе    ███████░░░ 2300/3000 (77%)
🚕 Такси   ████░░░░░░ 450/2000 (23%)
🍜 Еда     ██████████ 8500/8000 (106%) ⚠️
```

- Прогресс-бар меняет цвет (символ) в зависимости от процента:
  - < 50%: `░` (пусто) / `█` (заполнено) — зелёный
  - 50-80%: жёлтый (эмодзи ⚠️ или текст)
  - > 80%: красный (эмодзи 🔴)
  - > 100%: превышение (🔥)

**Хранение:**
- Тот же лист **Budgets** (колонки: Month, Category, Limit, Type)
- `Type = "category"` для категориальных лимитов
- Обновление: перезапись строки за текущий месяц

**Валидация:**
- Категория должна быть из списка `categories.py`
- Сумма ≥ 0 (0 = удалить лимит)
- Регистронезависимый поиск категории

**Acceptance:**
1. `/set_limit кофе 3000` → «Лимит на Кофе: 3000₴ на июнь»
2. `/set_limit кофе 0` → «Лимит на Кофе удалён»
3. `/limits` показывает все лимиты с тратами и прогресс-барами
4. Неизвестная категория → «Нет такой категории»
5. Отрицательная сумма → игнорируется

### REQ-03: Limit Alerts — `/limit_alerts`

**Current state:** Нет уведомлений о лимитах.
**Target state:** Кеша автоматически предупреждает при достижении порогов лимита.

**Описание:**
- `/limit_alerts` — показать текущий статус (вкл/выкл)
- `/limit_alerts on` — включить уведомления
- `/limit_alerts off` — выключить
- По умолчанию: включено (после установки первого лимита)

**Пороги и реакции:**
- **50%** — «Половина лимита на {категория} уже позади. Осталось {сумма}₴ до конца месяца.»
- **80%** — «Почти всё. Осталось всего {сумма}₴ на {категория}. Дальше — свои карманы.»
- **100%** (превышение) — жёсткий комментарий: «Всё. Лимит на {категория} исчерпан. Дальше работаешь на «спасибо».»

**Механизм:**
- Алёрт срабатывает **после** записи `/expense`
- Проверка всех активных лимитов → если порог достигнут → отправка предупреждения
- Пороги срабатывают **один раз** (флаг в user_data: `alerted_50_кофе = True`)
- При превышении — флаг сбрасывается в начале следующего месяца
- Если алёрты выключены — проверка пропускается

**Acceptance:**
1. `/limit_alerts on` → «Уведомления включены»
2. Трата достигает 50% лимита → приходит предупреждение
3. Трата достигает 80% → приходит второе предупреждение
4. Превышение лимита → жёсткий комментарий
5. Повторная трата на том же пороге → молчание (флаг сработал)
6. `/limit_alerts off` → уведомления не приходят

### REQ-04: Daily Quotes — `/quote`, `/quote_time`

**Current state:** 5 цитат-заглушек в `responses.py`.
**Target state:** Кеша присылает финансовую цитату дня с юмором и самоиронией.

**Описание:**
- `/quote` — случайная цитата из набора (15-20 штук)
- `/quote_time HH:MM` — установить время ежедневной цитаты
- `/quote_time off` — отключить ежедневные цитаты
- `/quote_time` — показать текущее время отправки

**Цитаты:**
- Пишутся на русском/суржике, в характере Кеши
- Финансовая тематика с юмором
- Минимум 20 уникальных цитат
- Примеры (расширить до 20):

QUOTES_PHASE2 = QUOTES + [

    "«Когда я вижу твои траты на маркетплейсах, мне хочется взять паузу и подышать.»",
    "«Скидка 50% — это всё равно минус 100% твоих денег, если ты не планировала покупку.»",
    "«Твоя самая вредная привычка — говорить «да ладно, один раз живём» каждый день.»",
    "«Инвестиции — это когда ты не покупаешь 15-ю пару кроссовок, а кладёшь деньги в банк.»",
    "«Категория «другое» — это как чёрная дыра: всё туда падает и не возвращается.»",
    "«Подушка безопасности — это не та, на которой ты спишь. Хотя спать на деньгах тоже вариант.»",
    "«Самая дорогая подписка — это подписка на иллюзию, что «в следующем месяце будет лучше».",
    "«Если ты считаешь каждую копейку в конце месяца — ты уже финансово грамотная. Поздравляю, ты бедная и грамотная.»",
    "«Баланс: доходы — это то, что ты заработала. Расходы — то, на что тебя не хватило.»",
    "«Финансовая цель на этот год — дожить до зарплаты, не заказывая пиццу каждый день.»",

- При старте бота: восстановить из `user_data` все активные расписания
- Время хранится в `user_data["quote_time"]`
- При `/quote_time HH:MM` — удалить старый job, создать новый

**Acceptance:**
1. `/quote` → случайная цитата
2. `/quote_time 09:00` → «Буду присылать цитату каждый день в 09:00»
3. В 09:00 приходит цитата (JobQueue)
4. `/quote_time off` → цитаты отключены
5. `/quote_time` → «Ежедневная цитата: 09:00 ✅ (или ❌)»

### REQ-05: Sticker & Emoji Settings — `/stickers`

**Current state:** Настроек стикеров/эмодзи нет.
**Target state:** Пользователь управляет использованием стикеров и эмодзи.

**Описание:**
- `/stickers` — показать текущие настройки:

```
🎨 Настройки стикеров
─────────────────────
Стикеры:   ✅ Вкл
Эмодзи:    ✅ Вкл
Частота:   Всегда
```

- Переключение через inline-кнопки:
  - Стикеры: Вкл / Выкл
  - Эмодзи: Вкл / Выкл
  - Частота: Всегда / Только крупные (>1000₴) / Выключены

**Набор стикеров:**
- 5-7 стикер-паков (file_id из Telegram)
- Категории: приветствие, большой расход, превышение лимита, доход, ночная покупка
- Если стикеры выкл — только текст
- Если частота «Только крупные» — стикер только при суммах > 1000₴

**Хранение:**
- Всё в `user_data`:
  - `user_data["stickers_enabled"]` — bool
  - `user_data["emoji_enabled"]` — bool
  - `user_data["sticker_frequency"]` — "always" / "large_only" / "off"

**Acceptance:**
1. `/stickers` показывает текущие настройки
2. Кнопка «Стикеры Вкл/Выкл» переключает
3. Кнопка «Эмодзи Вкл/Выкл» переключает
4. Кнопка «Частота» циклически меняет режим
5. При `sticker_frequency=off` стикеры не отправляются
6. Настройки сохраняются в сессии (user_data)

### REQ-06: Export — `/export`

**Current state:** Экспорта нет.
**Target state:** Пользователь может выгрузить данные в CSV или получить ссылку на Google Sheets.

**Описание:**
- `/export csv` — выгрузить ВСЕ транзакции в CSV
- `/export csv 30` — за последние 30 дней (число = количество дней)
- `/export csv 2026-05` — за май 2026
- `/export sheets` — отправить ссылку на Google Sheets таблицу

**Формат CSV:**
```csv
Date,Type,Amount UAH,Amount USD,Amount EUR,Category,Comment
28.05.2026,expense,350,,,Кофе,капучино
27.05.2026,income,50000,,,Зарплата,аванс
```

- Разделитель: запятая
- Кодировка: UTF-8 BOM (для корректного открытия в Excel)
- Файл отправляется как `InputFile` через `reply_document`
- Имя файла: `kesha_export_2026-05-31.csv`

**Техника:**
- Использовать встроенный `csv` модуль Python
- Писать в `io.StringIO()` → `encode("utf-8-sig")` → `BytesIO`
- Отправлять через `Update.message.reply_document(document=InputFile(...))`

**Acceptance:**
1. `/export csv` → файл CSV со всеми транзакциями
2. `/export csv 30` → только за последние 30 дней
3. `/export csv 2026-05` → только за май 2026
4. CSV открывается в Excel/Google Sheets корректно (UTF-8 BOM)
5. `/export sheets` → ссылка на Google Sheets таблицу
6. Если транзакций нет → «Нечего экспортировать, пустая таблица.»

### REQ-07: Daily Reminders — `/reminder`

**Current state:** Напоминаний нет.
**Target state:** Кеша каждый день напоминает подвести итоги и присылает сводку.

**Описание:**
- `/reminder` — показать текущие настройки
- `/reminder HH:MM` — установить время ежедневного напоминания
- `/reminder off` — отключить

**Содержание напоминания:**
```
📅 Итог дня: 31.05.2026

💰 Доход:  +5 000₴
💸 Расход: -1 230₴
📊 Баланс: +3 770₴

«Бюджет — это такой список «нет» на каждый день.»
```

- Содержит: итог дня (доход, расход, баланс) + случайная цитата
- Если за день не было операций: «Сегодня тишина. Либо ты ничего не тратила, либо я пропустил. Надеюсь, первое.»

**Расписание:**
- `JobQueue` — один job на пользователя
- При старте бота: восстановить из `user_data` время напоминания
- `user_data["reminder_time"]` — строка "HH:MM" или None
- `user_data["reminder_job_name"]` — имя job'а для удаления

**Acceptance:**
1. `/reminder` → «Напоминание: 20:00 ✅ (или ❌)»
2. `/reminder 20:00` → «Буду напоминать каждый день в 20:00»
3. В 20:00 приходит сообщение с итогом дня + цитатой
4. `/reminder off` → напоминание отключено
5. При старте бота расписание восстанавливается (если было)

### REQ-08: Comparison & Top — `/top`, `/compare`

**Current state:** Сравнения и топа нет.
**Target state:** Пользователь видит топ категорий и динамику месяц к месяцу.

**Описание `/top [N=5]`:**
- `/top` — топ-5 категорий расходов за текущий месяц
- `/top 10` — топ-10
- Показывает: категорию, сумму, процент от общих трат
```
📊 Топ расходов за июнь
────────────────────────
1. ☕ Кофе       8 500₴ (34%)
2. 🚕 Такси     5 200₴ (21%)
3. 🍜 Еда       4 100₴ (16%)
4. 🛍️ Маркетплейсы 3 000₴ (12%)
5. 👗 Одежда    2 300₴ (9%)
Всего: 25 100₴
```

**Описание `/compare`:**
- Сравнивает текущий месяц с предыдущим
```
📈 Сравнение: май → июнь
──────────────────────────
           Май      Июнь     Δ
Доход   45 000₴  52 000₴  +16%
Расход  32 000₴  25 100₴  -22%
Итог    +13 000₴ +26 900₴ +107%
```

- Расчёт дельты в процентах: `round((new - old) / old * 100)`%
- Если в прошлом месяце не было данных → «Не с чем сравнивать»
- Если в прошлом месяце доход/расход = 0 → показывать абсолютное значение

**Acceptance:**
1. `/top` → топ-5 категорий с суммой и процентом
2. `/top 10` → топ-10 категорий
3. `/compare` → таблица сравнения с дельтой
4. Если данных недостаточно → понятное сообщение
5. `/top` без трат → «Ничего не тратила. Горжусь. Или врёшь.»

## 3. Boundaries

### In Scope

- Месячный бюджет (общий лимит)
- Лимиты по категориям с автосбросом в начале месяца
- Уведомления при 50%, 80%, превышении лимита
- Цитаты дня (20 шт., русский/суржик, характер Кеши)
- Ежедневные цитаты по расписанию (JobQueue)
- Ежедневные напоминания с итогом дня (JobQueue)
- Экспорт в CSV (все / за N дней / за месяц)
- Топ категорий расходов
- Сравнение месяц к месяцу
- Настройки стикеров и эмодзи
- Хранение лимитов в Google Sheets (лист Budgets)
- Кэширование Budgets в памяти для снижения нагрузки на Sheets API

### Out of Scope

- Годовой бюджет — только месячный
- Импорт из CSV — только экспорт
- Редактирование бюджета через веб/PWA
- Мультипользовательские бюджеты
- Цели накопления (savings goals) — отдельная фаза
- Бюджет с учётом валют (только UAH)
- Автоматическое предложение лимитов на основе истории
- Экспорт в PDF или другие форматы — только CSV
- Синхронизация расписания с перезапусками через постоянное хранилище — JobQueue живёт пока запущен бот

---

## 4. Constraints

- **JobQueue сбрасывается при перезапуске бота** — расписание восстанавливается из `user_data` только для текущего пользователя (один пользователь, так что ок)
- **Google Sheets API**: 60 запросов/мин — кэшировать Budgets в памяти, обновлять не чаще раза в 5 минут
- **Telegram message limit**: 4096 символов — `/limits` и `/compare` укладываются, `/top` при 15 категориях тоже
- **user_data не персистентна** — после перезапуска бота все сессионные настройки (стикеры, время цитат, алёрты) сбрасываются. На момент Phase 2 это acceptable, т.к. пользователь один
- **CSV экспорт**: файл формируется в памяти (io.BytesIO) — для >10000 транзакций объём ~2-3 MB, влезает в лимит Telegram (50 MB)

## 7. Open Questions

1. **Хранение user_data при перезапуске** — сейчас user_data сбрасывается. Нужен ли простой JSON-файл (или SQLite) для персистентности настроек (стикеры, время цитат, время напоминания)? Или оставляем как есть на Phase 2?
2. **Стикеры** — нужны file_id реальных стикеров из Telegram. Либо используем существующие стикер-паки (через @Stickers бота) и hardcode file_id. Вопрос: какие стикеры нужны по характеру? Через кнопки в боте или Анна выберет сама?
3. **Цитаты** — утвердить финальный список из 20. Можно ли добавить шутки про Monobank/кешбек (учитывая Phase 4)?
4. **Google Sheets лист Budgets** — автосброс лимитов в начале месяца: создавать новую строку с тем же лимитом (копировать) или перезаписывать старую? Лучше копировать — остаётся история лимитов.
5. **Флаг алёртов в user_data** — при перезапуске бота флаги `alerted_50_*` сбрасываются, и алёрты могут прийти повторно. Стоит ли хранить их в Sheets (колонка Alert Flags)?
6. **Таймзона** — JobQueue в python-telegram-bot v21 использует UTC по умолчанию. Надо ли настраивать временную зону для пользователя (Киев, UTC+2/+3)? Или захардкодить Europe/Kyiv?
